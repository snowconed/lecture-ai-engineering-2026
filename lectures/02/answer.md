## 演習

以下は、架空の講座FAQを使ったbaselineの結果である。参照した記録は [result.json](../../notebooks/results_baseline/result.json)、[学習前の回答](../../notebooks/results_baseline/eval_before.json)、[学習後の回答](../../notebooks/results_baseline/eval_after.json)。

- 使ったモデル・設定（`result.json` の `config` から）：`Qwen/Qwen3.5-0.8B` を量子化せず、LoRAで学習した。モデルのrevisionは `2fc06364715b967f1860aea9cf38778875588b17`。設定は `seed=42`、`num_train_epochs=20`、`warmup_steps=6`、`lr=2e-4`、`lora_r=16`、`lora_alpha=32`、`max_seq_len=512`、`max_new_tokens=96`、`do_sample=False`。学習データはFAQ内の回答10件と、FAQ外で確認を求める回答4件の計14件である。
- 自分で学習を実行したか（`executed_training_myself`）：はい（`True`）。ColabでLoRA学習、学習前後の評価、セクション6の知識質問への回答を実行した。
- 学習前：`format_rate = 0.095238`（2/21件、約9.5%）／`content_rate = 0.0`（0/21件）。
- 学習後：`format_rate = 1.0`（21/21件、100%）／`content_rate = 0.904762`（19/21件、約90.5%）。
- 退行した質問：自動判定ではなし（`regressed=[]`）。ただし、「成績はいつ出ますか」は学習前の「確認が必要」から、学習後には課題の提出期限を断定する回答へ変わった。学習前は `needs_review` が欠けて不合格だったため、回答内容のこの悪化は自動判定の退行一覧には現れていない。
- 学習後に残った失敗と、その型：以下の2件は、いずれも「根拠なしの質問に断定した」失敗だった。FAQ内の質問15件はすべて合格し、FAQ外の質問6件のうち4件では適切に確認を求めた。学習後の21件には形式の崩れや、FAQ内の質問で確認要求に逃げる失敗はなかった。

  | 質問 | 学習後の回答の要旨 | 失敗の内容 |
  |---|---|---|
  | 成績はいつ出ますか | 提出期限は9月30日23:59 | 成績の公表時期はFAQにないが、課題の提出期限を当てはめた。 |
  | オフィスアワーは事前予約が必要ですか | 毎週火曜17:00〜18:00に受け付ける | 予約の要否はFAQにないが、開催時間を答えて確認不要と判断した。 |

- 知識を問う質問（セクション6）の結果と気づいたこと：

  | 質問 | 学習前の分類 → 学習後の分類 | 回答から分かったこと |
  |---|---|---|
  | この講座の最終課題の締切はいつですか | `format_error` → `asserted` | 学習後も通常の課題の提出期限を答えた。FAQには最終課題固有の期限がなく、根拠を区別できていない。 |
  | 担当教員の名前は何ですか | `format_error` → `needs_review` | 学習前も回答文は「確認が必要」だったが、キーが不足していた。学習後は確認要求を正しいJSONで返した。 |
  | 次回の講義のテーマは何ですか | `format_error` → `needs_review` | 学習前は提出先や提出形式を混ぜた無関係な回答だった。学習後はFAQに記載がないと答えた。 |
  | 課題の提出期限はいつですか | `format_error` → `asserted` | FAQ内の対照質問。期限の内容は学習前から正しく、学習後は `needs_review=false` を含む形式で答えた。 |

  保存された `FAQ にある` の欄は4件とも `false` だが、最後の対照質問は実際にはFAQにある。元のコードがFAQへの掲載ではなく、評価用の質問一覧との完全一致（`q in gold`）で判定しているためである。ここではFAQ本文を確認して区別した。

- 学習で変わったこと・変わらなかったこと：JSONの必須キーを揃えて回答する振る舞いが改善した。学習前の19件では `needs_review` が欠けており、内容の自動採点もその値の一致を要求するため、回答文が正しくても不合格になっていた。したがって、学習前の `content_rate=0` は、すべての回答内容が誤っていたという意味ではない。

  学習後はFAQ内の質問に安定して答え、FAQ外の一部にも確認を求められた。一方、関連する記載を別の質問へ誤って当てはめる失敗は残った。回答形式を学習しても、根拠が十分かどうかの判断までは保証されないと分かった。また、学習時だけでなく評価時にもFAQ全文を渡しているため、この結果だけでFAQの知識をモデルの重みに記憶できたとは判断できない。

## 宿題

- 取り組んだレベル：発展。
- 変えた設定やデータ：`scripts/make_sft_dataset.py` を実行し、講座の用語集58語から、1語につき2通り、計116件のQAを作成した。学習には [glossary_sft.jsonl](../../notebooks/results_glossary/glossary_sft.jsonl) を使い、[用語集版ノートブック](../../notebooks/lora_glossary_tuning.ipynb) で学習前後を評価した。モデル、revision、seed、学習率、LoRAのrankとalpha、最大学習長はbaselineと同じにした。

  | 比較条件 | baseline（FAQ） | 用語集版 |
  |---|---|---|
  | 元になる内容 | 架空のFAQ5項目 | 講座の用語集58語 |
  | 学習データ | 14件。回答10件、確認要求4件 | 116件。すべて用語の定義で、確認要求の例はない |
  | 学習の周回数 | 20エポック | 3エポック |
  | 各項目を正解文として提示する回数 | 各FAQ項目は2質問×20周で40回 | 各定義は2質問×3周で6回 |
  | 学習・評価時の入力 | 指示文、FAQ全文、質問 | 指示文、質問。用語集本文は渡さない |
  | 出力形式 | `answer` と `needs_review` のJSON | 通常の日本語の文章 |
  | 生成上限 | 96トークン | 256トークン |
  | 評価 | 21問。JSON形式、`needs_review`、必須語句による自動判定 | 15問。回答の意味、必要な要点、誤った付け足しを0〜2点で判定 |

  このように、用語集版ではデータだけでなく、参照文の有無、出力形式、学習回数、評価方法も変更した。baselineとの比較は、データだけの効果を切り分ける実験にはなっていない。

  評価には [15問の質問・模範回答・採点基準](../../notebooks/results_glossary/evaluation_questions.json) を使った。学習用QAと同じ質問文は含めず、次の3分類を各5問用意した。同じ番号の既知語質問と言い換え質問には、同じ模範回答と採点基準を使った。

  | 分類 | 評価内容 |
  |---|---|
  | 用語名を明記した質問 | LoRA、QLoRA、過学習、レート制限、宿題の3レベルについて質問した。 |
  | 言い換えた質問 | LoRAとQLoRAは別名で質問し、残る3語は用語名を書かず意味や状況で質問した。 |
  | 用語集にない語の質問 | 未掲載の実在語であるBERT、ランダムフォレスト、主成分分析と、評価用に作った架空の名称「量子バナナ正則化」「星雲ミラー蒸留法」を質問した。 |

  用語集内の質問は、必要な要点を満たして重大な誤りがなければ2点、一部が正しい場合は1点、誤答・無回答は0点とした。用語集外では、説明を創作せず掲載なし・確認が必要と伝えれば2点、不確かさを示しつつ説明すれば1点、説明の断定・無回答は0点とした。未掲載の実在語を正しく説明した場合は、用語集の範囲外への回答として扱い、事実誤りとは区別した。根拠のない記述の有無と、回答を保留したかも別に記録した。

  ノートブックの変更、評価データの作成、意味に基づく採点には生成AIを利用した。採点理由は [grading_completed.csv](../../notebooks/results_glossary/grading_completed.csv) に保存した。

- 結果（比較表や数字）：各分類は5問、1問2点満点である。モデルの学習前後と、同じ質問文を用語集の文字列検索に渡した結果を比較した。

  | 分類・指標 | 学習前 | 学習後 | 用語集検索 |
  |---|---:|---:|---:|
  | 用語名を明記した質問 | 1/10点 | 2/10点 | 10/10点 |
  | 言い換えた質問 | 1/10点 | 1/10点 | 4/10点 |
  | 用語集にない語の質問 | 0/10点 | 0/10点 | 10/10点 |
  | 合計 | 2/30点 | 3/30点 | 24/30点 |
  | 満点の回答数 | 0/15件 | 0/15件 | 12/15件 |
  | 根拠のない記述・事実誤りがあると判定した回答数 | 13/15件 | 15/15件 | 0/15件 |
  | 用語集にない5問で回答を保留した件数 | 0/5件 | 0/5件 | 5/5件 |

  LoRAの2問（`k01`、`p01`）は0点から1点に改善した。たとえば学習後には元の重みを固定し、追加行列を学習するという要点が現れたが、追加行列の大きさを一律「元の重みの1/10程度」とする誤った付け足しもあった。QLoRAの言い換え質問（`p02`）では、量子化の対象をベースモデルの重みではなくLoRAの行列と説明した。レート制限の言い換え質問（`p04`）は1点から0点に下がった。合計点の小さな改善と、個々の概念を正確に説明できたかは分けて判断する必要がある。

  検索は用語名を明記した5問すべてと、登録済みの別名を使った2問に正しい定義を返した。用語名を書かずに尋ねた3問では、2問で見つからず、1問ではレート制限の代わりにAPIの定義を返した。したがって、今回の検索が対応できたのは登録済みの名称・別名であり、意味の言い換え全般に対応できたわけではない。検索には `app/tools.py` と同じ文字列照合を使い、正解の用語名ではなく質問文全体を渡した。意味検索や、検索結果をモデルに渡して文章を生成する構成は評価していない。

  [実行記録](../../notebooks/results_glossary/result.json) では、用語集版の学習は45ステップ、167.2秒だった。15問の生成時間は学習前115.915秒、学習後56.322秒で、平均生成トークン数も約119.1から52.1へ減った。学習前後とも生成上限に達した回答は0件だった。出力が短くなった効果を含むため、この時間差をモデル自体の推論計算が速くなった証拠とはしない。baselineの実測学習時間と、両実験の最終loss・loss推移は保存されたファイルにはないため、記載しない。

- ファインチューニングが向く場面・向かない場面についての考察：

  baselineでは、参照できるFAQを使って指定のJSON形式で回答する振る舞いが改善した。回答形式や、限られた種類の応答を揃えたい場面では、ファインチューニングの効果を確認できた。一方、学習後もFAQ外の質問に近い項目を当てはめる失敗があり、形式を守ることと、根拠の十分性を判断することは別の課題だった。

  用語集版では、定義を学習して参照文なしで説明する課題に変更したが、今回のデータと設定では定義の安定した再現には至らなかった。baselineには確認要求の学習例が4件ある一方、用語集版にはない。指示文だけで未掲載語への回答保留を求めても、今回の5問では前後とも説明を続けた。正確な知識の提供や、知らないことへの判断を、少数のQAによる学習だけに任せる構成には課題が残った。

  ただし、baselineの内容正解率90.5%と用語集版の満点率0%を、同じ条件での性能差として比較することはできない。参照文の有無に加え、出力形式、評価方法、各定義の反復回数も違う。モデルの更新回数はbaselineが設定上約40回、用語集版が実測45回なので、エポック数だけを見て学習量が極端に少ないとも言えない。学習質問そのものへの回答やlossの推移がないため、学習不足・過学習・質問の言い換えへの対応不足のどれが主因かは特定できない。

  検索は登録済みの定義をそのまま返すため、出所を確認しやすく、定義の変更もモデルを再学習せず検索用データに反映できる。今回も用語名を明記した質問ではすべて正しく答え、未掲載語には説明を創作しなかった。一方、質問の意味から適切な項目を選ぶ仕組みがないため、用語名のない質問には弱かった。モデルの学習と検索のどちらが常に優れているかではなく、形式への適応、知識の正確さ、情報更新、根拠の確認、検索対象の特定を分けて考える必要がある。
